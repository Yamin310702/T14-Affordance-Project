# 1. Research Topic

My self-research topic is **T14: 3D Affordance Prediction**.

The goal of 3D affordance prediction is to predict what actions can be performed on different parts of a 3D object.

For example:

- a handle may support **grasping**
- a chair seat may support **sitting**
- a button may support **pressing**
- a container may support **pouring**

The input is a 3D point cloud representing an object.

The output is a point-wise affordance prediction.

Conceptually:

```text
3D Point Cloud
      +
Affordance Text
      ↓
3D Affordance Model
      ↓
Affordance prediction
for each point
```

For this project, I use **OpenAD** as the main executable baseline.

---

# 2. Baseline: OpenAD

OpenAD performs open-vocabulary affordance detection on 3D point clouds.

The PointNet++ version of OpenAD contains two important parts:

```text
3D Point Cloud
      ↓
PointNet++
      ↓
512-D point features
      │
      │ similarity
      ↓
CLIP text features
      ↑
Affordance text
```

For each 3D point, OpenAD compares the learned point feature with CLIP text features representing affordance names.

The model then predicts which affordance best matches each point.

---

# 3. OpenAD Model Architecture

The baseline used in this project is:

```text
OpenAD + PointNet++
```

From `models/openad_pn2.py`, PointNet++ first extracts point features using Set Abstraction layers:

```text
Input XYZ
   ↓
SA1
   ↓
SA2
   ↓
SA3
```

Feature Propagation layers then recover point-level features:

```text
SA3
 ↓
FP3
 ↓
FP2
 ↓
FP1
 ↓
Conv1D
 ↓
512-D point feature
```

The model also encodes affordance text using CLIP.

The final prediction is based on cosine similarity between point and text features.

The relevant operation is conceptually:

```text
point feature · text feature
--------------------------------
||point feature|| ||text feature||
```

A learned `logit_scale` is applied, followed by:

```python
F.log_softmax(x, dim=1)
```

Therefore, the final output contains log-probabilities over affordance classes for every point.

# 6. macOS / MPS Compatibility Changes

Because the original code expects CUDA, I made several small compatibility changes.

The goal was **not to change the OpenAD algorithm**, but only to make inference run on my Apple M3 Pro.

## 6.1 Gorilla NVML problem

The Gorilla utility package tried to initialize NVIDIA NVML.

This produced an error because the Mac does not have an NVIDIA GPU.

The import:

```python
from .gpu import (get_free_gpu, set_cuda_visible_devices)
```

was disabled in Gorilla's `utils/__init__.py`.

A backup of the original file was kept.

A remaining warning about `pynvml` is harmless for the current experiment.

---

## 6.2 Device selection

The original CUDA-specific model setup was changed to:

```python
device = torch.device(
    "mps" if torch.backends.mps.is_available()
    else "cpu"
)
```

The model is then loaded using:

```python
model = build_model(cfg).to(device)
```

---

## 6.3 Checkpoint loading

Checkpoint loading was changed to use the selected device:

```python
model.load_state_dict(
    torch.load(
        args.checkpoint,
        map_location=device
    )
)
```

CUDA-specific evaluation code was replaced by:

```python
device = next(model.parameters()).device

data = data.float().to(device)
```

This allowed evaluation to run correctly using MPS.

# 15. Initial Research Idea: Geometry Smoothing

At first, I considered using **k-nearest-neighbor score propagation**.

The idea was that partial observations might produce fragmented predictions.

For each point \(i\), a smoothed affordance score could be calculated using nearby points:

```text
new score =
original score
+
neighbor information
```

Conceptually:

\[
s'_i =
(1-\alpha)s_i
+
\alpha
\frac{1}{k}
\sum_{j\in N_k(i)}s_j
\]

Possible experiments could vary:

```text
k = 3, 5, 10, 20
```

and different values of:

```text
alpha
```

However, before implementing this method, I decided to inspect the actual OpenAD failures.

This was important because k-NN smoothing would only make sense if the prediction errors were spatially fragmented.

# 20. Why k-NN Smoothing Became Less Convincing

The three visualized failures did not show the expected pattern:

```text
correct prediction
   ↓
fragment
   ↓
fragment
   ↓
missing gap
```

Instead, the target affordance disappeared completely after the final classification.

This suggested that simple spatial smoothing might not address the main problem.

If no neighboring points are predicted as the target class, there may be little useful target signal for k-NN to propagate.

Therefore, I paused the k-NN idea instead of implementing it immediately.

# 21. Raw Prediction Score Analysis

The visualization only showed the final `argmax` prediction.

However, a missing target prediction does not necessarily mean OpenAD has no target signal.

For example:

```text
none   = 0.43
clothe = 0.40
```

would still produce:

```text
prediction = none
```

even though the model has a strong `clothe` response.

To investigate this, I created:

```text
analyze_failure_scores.py
```

The script examines OpenAD probabilities **before the final argmax decision**.

For ground-truth target points, it calculates:

- mean probability for every affordance,
- ranking of the correct affordance,
- winning argmax class,
- mean correct-target probability,
- maximum correct-target probability,
- percentage of correctly classified target points.

# 25. Current Observed Failure Pattern

The three inspected partial-view zero-IoU examples show a consistent pattern.

| Target | Object | GT Target Points | `none` Mean | Target Mean | Target Rank | `none` Argmax |
|---|---|---:|---:|---:|---:|---:|
| clothe | Hat | 930 | 0.432 | 0.255 | #2 | 100% |
| wrap | Vase | 1,539 | 0.636 | 0.073 | #2 | 100% |
| pour | Vase | 563 | 0.644 | 0.058 | #2 | 100% |

The interesting observation is:

```text
Correct affordance is not random.
Correct affordance is ranked #2 in all three examples.

BUT

"none" consistently wins.
```

Therefore, my current description of the observed failure is:

> **Target–background (`none`) confusion in selected partial-view OpenAD failures.**

This is more precise than simply saying that OpenAD cannot recognize the affordance.

---

# 26. Important Limitation of the Current Failure Analysis

The three examples were intentionally selected from low-IoU samples.

Therefore, I should **not** conclude yet that:

> OpenAD generally predicts `none` for partial point clouds.

The current evidence only supports the narrower statement:

> In three inspected zero-IoU partial-view failures (`clothe`, `wrap`, and `pour`), the `none` class dominated the correct affordance on all ground-truth target points, even though the correct target was the second-highest class on average.

A dataset-level analysis is still required.

# 27. Current Research Direction

Initially, I considered a geometry-based method:

```text
k-NN score propagation
```

because I expected partial-view predictions to become spatially fragmented.

However, the observed examples do not strongly support that explanation.

The current evidence instead suggests investigating the **text/semantic representation** used by OpenAD.

A possible lightweight modification is **prompt ensembling**.

Original OpenAD may represent an affordance using a short label such as:

```text
clothe
```

A richer representation could use several semantically related descriptions.

Conceptually:

```text
Prompt 1 ─┐
Prompt 2 ─┤
Prompt 3 ─┼─→ CLIP embeddings → average → affordance representation
Prompt 4 ─┤
Prompt 5 ─┘
```

The resulting text embedding can then be compared against the same point features.

This changes only the text representation while keeping the main OpenAD model and checkpoint fixed.

---

# 28. Provisional Research Question

My current provisional research question is:

> **Can richer text prompts reduce target–background (`none`) confusion in OpenAD for partial-view 3D affordance prediction?**

This research question is still provisional.

Before finalizing it, I plan to perform dataset-level failure analysis to determine whether `none` dominance is common across partial-view validation samples.

---

# 29. Provisional Hypothesis

My current hypothesis is:

> **Averaging CLIP embeddings from multiple semantically equivalent affordance prompts will increase the correct affordance score relative to the `none` class and improve point-wise IoU on partial-view data compared with OpenAD's original single-word text representation.**

This hypothesis is falsifiable.

For example, it would not be supported if:

```text
prompt ensemble IoU <= original OpenAD IoU
```

or if richer prompts increase false positives enough to reduce overall IoU.
